API Reference

HTTP Client — lib/api.ts

A custom fetch-based HTTP client with automatic JWT token injection, 15-second timeout, and transparent token refresh.

Exported Interface
export const api = { get: (endpoint: string) => Promise<ApiResponse> post: (endpoint: string, body: object) => Promise<ApiResponse> patch:(endpoint: string, body: object) => Promise<ApiResponse> setTokens: (access: string, refresh: string) => Promise<void> getTokens: () => Promise<{ accessToken, refreshToken }> clearTokens: () => Promise<void> }
ApiResponse Interface
interface ApiResponse<T = any> { success: boolean; message?: string; data?: T; status?: number; [key: string]: any; // Extra fields like `user`, `accessToken` }
Request Headers
Header Value Notes
Content-Type application/json Always set
Accept-Language i18n.language Current locale (en, ar, ur, etc.)
Authorization Bearer {token} Only when token exists in SecureStore

Token Management

Tokens are stored in Expo SecureStore (encrypted keychain on iOS, encrypted SharedPreferences on Android):

Key Purpose
tn_access_token Short-lived JWT for API authentication
tn_refresh_token Long-lived token for obtaining new access tokens

Token Refresh Flow

When a request returns 401 Unauthorized, the client automatically attempts a token refresh:

401 Received (not /refresh or /login) │ ├── Has refresh token? │ ├── NO → clearTokens() → return { success: false, message: 'unauthorized' } │ └── YES │ ├── Already refreshing? (isRefreshing flag) │ │ ├── YES → Queue request via addRefreshSubscriber() → wait │ │ └── NO → Set isRefreshing = true │ │ ├── POST /app-user/mobile/refresh { refreshToken } │ │ ├── Success? → setTokens(new) → onRefreshed(token) → retry original request │ │ └── Fail? → clearTokens() → return unauthorized │ └── When refresh completes → all queued subscribers retry their original requests
Concurrent Requests: If multiple requests fail with 401 simultaneously, only one refresh is sent. Others are queued via the subscriber pattern and retried after the refresh completes.

Error Handling

Scenario Response
Request timeout (15s) { success: false, message: 'network_error', error: 'timeout' }
Network failure { success: false, message: 'network_error' }
Invalid JSON response { success: false, message: 'invalid_json', status: N }
401 with no refresh token { success: false, message: 'unauthorized', status: 401 }
Refresh token expired { success: false, message: 'unauthorized', status: 401 } + tokens cleared

Auth Endpoints

POST /app-user/mobile/login

Authenticate with email and password.

Request Body
{ "email": "string", "password": "string" }
Success Response
{ "success": true, "accessToken": "jwt...", "refreshToken": "jwt...", "user": { "_id", "email", "username", "profile": {...} } }
POST/app-user/mobile/signup

Register a new user with email.

Request Body
{ "email": "string", "password": "string", "agreed": true, "marketing_opt_in": false }
Success Response
{ "success": true, "accessToken": "jwt...", "refreshToken": "jwt...", "user": { ... , "email_verified": false } }
POST/app-user/mobile/auth/google

Authenticate with Google OAuth2 ID token.

Request Body
{ "credential": "google-id-token" }
Notes

Google users are auto-verified (email_verified: true). Creates account if new.

GET/app-user/mobile/me

Fetch current authenticated user with full profile. Used on app launch and after login.

Success Response
{ "success": true, "user": { "_id", "email", "username", "email_verified", "status", "visible", "status_online", "profile": { "profileName", "gender", "dob", "nationality", "mother_tongue", "marital_status", "height", "education", "sect", "smoking", "alcohol", "current_location": { "city", "country" }, "profile_manager", ... } } }
POST/app-user/mobile/refresh

Exchange refresh token for new access token. Called automatically by the HTTP client.

Request: { "refreshToken": "string" } Response: { "success": true, "accessToken": "new-jwt", "refreshToken": "new-or-same" }
POST/app-user/mobile/logout

Invalidate refresh token server-side. Client fires and forgets, then clears local tokens.

Request: { "refreshToken": "string" }
POST/app-user/resend-verification

Resend email verification link.

Request: { "email": "string" }

Profile Endpoints

POST/profile/new

Create initial profile (Step 1 only). Sets immutable fields.

{ "religion": "islam", "profileName": "string (max 15, alphanumeric)", "gender": "male" | "female", "dob": "YYYY-MM-DD", "nationality": ["string", "string"], "grew_up_in": "country_code" }
PATCH/profile/update

Update profile fields (Steps 2–9). Accepts partial data.

See Profile Setup for per-step payloads.

GET/masterdata/:type

Fetch master list values for select fields.

Type Used In
height Step 4
complexion Step 4
ethnic_group Step 4
education Step 5
occupation Step 5
designation Step 5
income Step 5
sect Step 6
sect_type Step 6
caste Step 6
Response Shape
{ "success": true, "data": [{ "_id": "...", "name": "...", "description": "..." }, ...] }
GET/profile/places/details?place_id=...&language=en

Google Places backend proxy (Step 8). Also uses direct Google Places Autocomplete API on client.
