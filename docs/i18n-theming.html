Internationalization & Theming

i18n Setup — lib/i18n.ts

The app uses i18next + react-i18next for translations. Configuration:

import i18n from 'i18next'; import { initReactI18next } from 'react-i18next'; i18n.use(initReactI18next).init({ fallbackLng: 'en', defaultNS: 'common', ns: ['common', 'countries', 'nationalities', 'languages', 'ethnic_groups', 'designations'], interpolation: { escapeValue: false }, resources: { en: { common: require('@/locales/en/common.json'), ... }, ar: { common: require('@/locales/ar/common.json'), ... }, // ... ur, fr, de, tr } });

RTL Support

RTL is a first-class concern. The useLanguage() hook exposes isRTL which is true for ar and ur.

Where RTL is Applied
Component RTL Behavior
Input.tsx flexDirection: 'row-reverse', icon margins swap, textAlign: 'right', writingDirection: 'rtl'
SelectField flexDirection: 'row-reverse', textAlign: 'right'
FieldLabel Row reverse for label + asterisk
ErrorText textAlign: 'right'
Auth pages Header row, forgot password, footer, Google terms — all flip direction
How to Add RTL to a New Component
import { useLanguage } from '@/hooks/useLanguage'; const { isRTL } = useLanguage(); // Flip flex direction style={{ flexDirection: isRTL ? 'row-reverse' : 'row' }} // Flip text alignment style={{ textAlign: isRTL ? 'right' : 'left' }} // Swap icon margins style={{ [isRTL ? 'marginLeft' : 'marginRight']: scale(10) }} // Text writing direction style={{ writingDirection: isRTL ? 'rtl' : 'ltr' }}

Usage in Components

import { useLanguage } from '@/hooks/useLanguage'; function MyScreen() { const { t, isRTL, language, changeLanguage } = useLanguage(); return ( <View> {/* Simple translation */} <Text>{t('auth.login_title')}</Text> {/* With namespace */} <Text>{t('countries:united_states')}</Text> {/* With default fallback */} <Text>{t('step_1.dob', { defaultValue: 'Date of Birth' })}</Text> {/* Change language */} <Button onPress={() => changeLanguage('ar')} title="Switch to Arabic" /> </View> ); }

Theming

Dark Mode System

Three-layer architecture for dark mode:

┌────────────────────────────────────────────────────────────────┐ │ themeStore.ts (Zustand + persist) │ │ Stores: mode = "light" | "dark" | "system" │ │ Persisted to: AsyncStorage ("tonikah-theme-preference") │ ├────────────────────────────────────────────────────────────────┤ │ useTheme.ts (Custom Hook) │ │ Reads: mode from store + useColorScheme() from React Native │ │ Computes: isDark = mode==="dark" ? true │ │ : mode==="light" ? false │ │ : systemColorScheme === "dark" │ │ Returns: { theme, isDark, toggleTheme, setTheme } │ ├────────────────────────────────────────────────────────────────┤ │ ThemeProvider.tsx (NativeWind) │ │ Sets NativeWind's colorScheme based on computed dark mode │ │ Enables className dark: variants (dark:bg-slate-900 etc.) │ └────────────────────────────────────────────────────────────────┘
Critical: For form inputs (Input.tsx, SelectField), we use explicit style objects with isDark checks rather than NativeWind classes. This ensures dark mode colors work reliably in TextInput components where NativeWind dark: variants can be inconsistent.

Responsive Scaling — hooks/useResponsive.ts

The scale() function scales pixel values based on screen width relative to 375px (iPhone SE baseline):

import { Dimensions } from 'react-native'; const { width } = Dimensions.get('window'); const BASE = 375; export const scale = (size: number): number => (width / BASE) * size; // Usage: style={{ fontSize: scale(14), padding: scale(16), borderRadius: scale(12) }} // Examples: // iPhone SE (375px): scale(14) → 14 // iPhone 15 (393px): scale(14) → 14.7 // iPad (768px): scale(14) → 28.7
