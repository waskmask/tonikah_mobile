Profile Setup (9-Step Wizard)

Overview

After auth + email verification, new users complete a 9-step profile wizard. Each step is a separate route under (profile-setup)/. Step 1 creates the profile via POST /profile/new; steps 2–9 update it via PATCH /profile/update.

The app does not require completing all steps in a single session. On re-login, getIncompleteStep(profile) detects the first incomplete step and redirects there.

Step Detection Logic

The profileSetupStore.getIncompleteStep(profile) function checks fields in order:

Step Required Field Check
1 profileName Non-empty string
2 mother_tongue Non-empty string
3 marital_status Non-empty string
4 height Non-empty string/number
5 education Non-empty string
6 sect Non-empty string
7 smoking Non-empty string
8 current_location.city Nested city field exists
9 profile_manager Non-empty string

Step 1Profile Basics

Route: step1.tsx • API: POST /profile/new

Fields
profileName Text input, max 15 chars, alphanumeric only
gender SingleSelectSheet: "male" | "female"
dob DateTimePicker (spinner), max 18 years back, format DD.MM.YYYY
nationality MultiSelectSheet, max 2, title-cased labels
grew_up_in SingleSelectSheet, country list
API Payload
{ "religion": "islam", "profileName": "string", "gender": "male" | "female", "dob": "YYYY-MM-DD", "nationality": ["string", "string?"], "grew_up_in": "country_code" }

Step 2Language & Culture

Route: step2.tsx • API: PATCH /profile/update

mother_tongue SingleSelectSheet, title-cased language names
spoken_languages MultiSelectSheet, multiple selection allowed

Step 3Marital & Family

Route: step3.tsx • API: PATCH /profile/update

marital_status "never_married" | "divorced" | "widowed" | "annulled" | "separated"
children "no_children" | "1" | "2" | "3" | "4_plus"
family_type "nuclear" | "joint" | "other"
family_values "traditional" | "moderate" | "liberal"

Step 4Physical Attributes

Route: step4.tsx • API: PATCH /profile/update • Masterdata: height, complexion, ethnic_group

height Masterdata select (e.g., "5ft 4in / 163cm")
complexion Masterdata select (e.g., "fair", "medium", "dark")
body_type "slim" | "average" | "athletic" | "heavy"
ethnic_group Masterdata select

Step 5Education & Career

Route: step5.tsx • API: PATCH /profile/update • Masterdata: education, occupation, designation, income

education Masterdata select
occupation Masterdata select
designation Masterdata select
annual_income Masterdata select

Step 6Religious Details

Route: step6.tsx • API: PATCH /profile/update • Masterdata: sect, sect_type, caste

sect Masterdata select (e.g., "sunni", "shia", "ibadi")
sect_type Masterdata select (e.g., "hanafi", "shafi", "maliki", "hanbali")
born_muslim "yes" | "no"
prayer_frequency "always" | "mostly" | "sometimes" | "rarely" | "never"
caste Masterdata select (optional)

Step 7Lifestyle

Route: step7.tsx • API: PATCH /profile/update

smoking "never_smoke" | "quit_smoking" | "occasionally_smokes" | "smokes_regularly" | "trying_to_quit"
alcohol "never" | "occasionally" | "regularly" | "quit"
diet "halal_only" | "vegetarian" | "vegan" | "no_restriction"

Step 8Location

Route: step8.tsx • API: PATCH /profile/update • Google Places Autocomplete

current_location.city Google Places autocomplete search
current_location.country Auto-populated from city selection
current_location.lat Auto-populated latitude
current_location.lng Auto-populated longitude
Uses GOOGLE_MAPS_API_KEY from config.ts for the Places Autocomplete API. A backend proxy at /profile/places/details is also available.

Step 9Profile Manager

Route: step9.tsx • API: PATCH /profile/update

profile_manager "self" | "parent" | "sibling" | "relative" | "friend" | "other"

After step 9, getIncompleteStep() returns 0 → user is redirected to /(tabs)/home.

Shared Patterns Across Steps

UI Components
  • ProgressBar at top (current step highlighted)
  • FieldLabel + SelectField from FormField.tsx
  • SingleSelectSheet / MultiSelectSheet bottom sheets
  • GradientButton Continue/Finish CTA
  • All support dark mode + RTL
Data Flow
  • Masterdata fetched from /masterdata/:type → cached in profileSetupStore
  • Enum options built from hard-coded constants per step
  • Fallback labels use .replace(/_/g, ' ') + title-case
  • On success → navigate to step{N+1}
  • On final step → navigate to /(tabs)/home
