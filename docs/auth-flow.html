Authentication Flow

Overview

The app supports two auth methods: Email/Password and Google OAuth2. Both methods result in JWT tokens stored in SecureStore. The architecture:

┌──────────────┐ ┌─────────────┐ ┌──────────────┐ ┌────────────┐ │ login.tsx │─────▶│ authStore │─────▶│ authService │─────▶│ api.ts │ │ signup.tsx │ │ (Zustand) │ │ (Service) │ │ (HTTP) │ └──────────────┘ └──────┬──────┘ └──────────────┘ └────────────┘ │ ┌────────▼────────┐ │ SecureStore │ ← JWT tokens │ (Encrypted) │ └─────────────────┘

Email Login Flow

1
User enters email and password in login.tsx
2
Button enables after user types ≥3 characters (no blur required)
3
On submit: authStore.login(email, password) called
4
Store calls authService.login() → POST /app-user/mobile/login
5
On success: api.setTokens(accessToken, refreshToken) → stored in SecureStore
6
Store sets user and isAuthenticated = true
7
Router navigates to / → index.tsx decision tree runs (checks verification, profile completeness)
Email not verified: If user.email_verified === false, the user is redirected to verify-email.tsx before they can access root index.

Email Signup Flow

1
User fills: email, password, confirm password
2
User checks Terms & Conditions checkbox (required) and optionally marketing opt-in
3
Zod validates password strength (8+ chars, uppercase, lowercase, number, special char)
4
authStore.signup() → POST /app-user/mobile/signup
5
On success: tokens stored, but email_verified: false. Shows success toast.
6
Redirect to verify-email.tsx with email param

Google Auth Flow

1
User taps "Sign in with Google" button
2
authStore.googleAuth() calls signInWithGoogle() from lib/googleSignIn.ts
3
Google native module shows account picker → returns idToken
4
If user cancels → returns { cancelled: true }, no error shown
5
authService.googleAuth({ credential: idToken }) → POST /auth/google
6
Backend verifies token, creates/finds user, returns JWT tokens + email_verified: true
7
Tokens stored, user set, navigates to / (skips email verification)

Email Verification

Email-registered users must verify before accessing the main app:

  • verify-email.tsx shows "Check your inbox" with the user's email
  • Resend: authService.resendVerification(email) → POST /app-user/resend-verification
  • Go to Login: Button navigates back to login (user can log in after verifying via email link)
  • On next login: index.tsx checks user.email_verified — if still false, redirects back to verify-email

Session Restoration

On app launch, _layout.tsx calls authStore.restoreSession():

1. Check SecureStore for access token 2. If no token → set isAuthenticated=false, isRestoringSession=false → done 3. If token exists → call authService.me() (GET /app-user/mobile/me) • Success → set user + isAuthenticated=true • 401 → api.ts auto-refreshes token → retry /me • Fail → clearTokens() → set isAuthenticated=false 4. Set isRestoringSession=false → index.tsx decision tree runs

Logout

1. authStore.logout() called 2. Get refresh token from SecureStore 3. Fire-and-forget: POST /app-user/mobile/logout { refreshToken } 4. Clear both tokens from SecureStore 5. Set user=null, isAuthenticated=false 6. Router redirects to /(auth)/login

Security Considerations

Token Storage

JWT tokens stored in Expo SecureStore (iOS Keychain / Android EncryptedSharedPreferences). Never in AsyncStorage or local state.

Automatic Refresh

401 responses trigger transparent token refresh. Concurrent requests queue behind a single refresh. Failed refresh clears all tokens.

Request Timeout

All API requests abort after 15 seconds via AbortController. Returns network_error.

Google OAuth

Only the idToken is sent to the backend. The backend verifies it independently with Google. No user credentials are stored client-side.
